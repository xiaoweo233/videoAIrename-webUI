# 视频 AI 重命名助手 — 应用方案 v1.0

> 输入依据：
> ① 参考项目 `cuicui-V5/video_ai_rename`（三阶段并发流水线 + Whisper + ExifTool）
> ② `D:/qita/ai/111/batch_rename.py` + `运行视频重命名.bat`（纯命令行版，OpenAI 兼容接口）
> ③ `D:/qita/ai/1/ai视频重命名APP.txt`（手写需求要点）
> ④ 既有 `video_ai_rename_GUI`（Tkinter 桌面版，含 PRD/DESIGN）与 `111/video_ai_web`（Web 版）
>
> 目标落地目录：`D:/qita/ai/1/videoAIrenameAPP/`

---

## 0. 一句话结论

**不要重写引擎，要换外壳。** 你已经有三份能跑的实现，真正缺的不是功能，而是「一个装到设备上、双击就能用、改过的配置会自动保存、所有垃圾不乱丢」的**应用形态**。方案采用 **引擎内核（纯 Python，无 UI 依赖）+ 可插拔外壳（桌面 / Web）** 的双层结构，一次实现，两种访问方式。

## 1. 项目定位

| 项 | 内容 |
| --- | --- |
| 产品名 | 视频 AI 重命名助手（暂定 `vair`） |
| 一句话 | 拖入一个文件夹，自动看懂每个视频讲了什么，重命名、写元数据、生成 NFO/SRT |

## 2. 现状盘点：三份资产怎么用

| 资产 | 已有能力 | 可复用度 | 主要问题 |
| --- | --- | --- | --- |
| `batch_rename.py`（111） | 抽帧、OpenAI 兼容调用、重试/熔断、NFO、长路径、跳过已处理、dry-run | **高**，逻辑成熟可直接搬 | 单文件 900 行；无 Whisper；无 ExifTool；配置靠 bat 环境变量 |
| `video_ai_rename`（参考仓库） | Whisper 转写、ExifTool 零拷贝写元数据、时间戳还原、三阶段并发、软水印 | **高**，是流水线骨架的来源 | 面向 Gemini 云端；无 GUI；依赖装在全局 |
| `video_ai_rename_GUI` | 完整分层架构、EventBus、StopToken、CUDA 自动补齐、config.json、便携化 | **极高**，直接作为新项目骨架 | Tkinter 外观偏老旧；分发仍是"解压 + 双击 bat" |
| `111/video_ai_web` | Web 交互、文件树选择、任务管理 | **中**，UI 经验可借鉴 | 与桌面版引擎重复实现，两处维护 |

**结论**：以 `video_ai_rename_GUI` 的 `app/core/` 作为**引擎内核**的唯一真源，把它的 GUI 层替换为可插拔外壳；Web 版不再自己实现流水线，改为调用同一内核。

## 3. 需求落地对照表

把 `ai视频重命名APP.txt` 的每条要求翻译成设计约束：

| # | 原始需求 | 设计约束 | 落点 |
| --- | --- | --- | --- |
| 1 | 桌面端 / 手机 App，装到设备里可离线运行 | 桌面做**免安装便携包**（解压即用）；移动端不做原生 App，改**局域网 Web** | 见 §4 |
| 2 | 探测 → 抽帧(并发) + 转写(GPU 串行) → 多模态 AI → ExifTool 写元数据 → 重命名 + 时间戳还原 → NFO/SRT | 五阶段流水线，阶段间用队列解耦 | 见 §6 |
| 3 | 术语表（ffmpeg/Whisper/NFO/SRT…） | 文档与界面**双语提示**：专业名 + 一句人话；设置页每项带「这是什么」 | `docs/术语表.md` + GUI tooltip |
| 4 | 运行日志，每个功能、AI 模型、处理过程全部显示 | 分级日志（DEBUG/INFO/WARN/ERROR）+ **单文件推理时间线**（模型名、帧数、字幕字数、耗时）+ 实时推送到界面 | 见 §9 |
| 5 | 每个功能单独开关；产物全在应用自己目录；配置自动存 config.json | 每个能力一个布尔开关；启动时 env 重定向到 APP_ROOT；配置变更即写盘 | 见 §7、§8 |

## 4. 形态决策（重要）

### 4.1 三种形态对比

| 形态 | 能做 Whisper GPU 转写吗 | 分发成本 | 维护成本 | 评价 |
| --- | --- | --- | --- | --- |
| Windows 桌面便携包 | ✅ 完全本地 | 低（PyInstaller 打包 / 目录分发） | 低 | **主力形态** |
| 局域网 Web（同内核） | ✅ 跑在宿主机上 | 极低（已有内核，加一层 API） | 极低 | **辅助形态**，顺带解决"手机访问" |
| 原生 Android / iOS App | ❌ 移动端跑不了 large-v3；ffmpeg/exiftool 移植代价大 | 极高 | 极高 | **不建议** |

### 4.2 推荐方案：一核两壳

```
                    ┌──────────────────────────────┐
                    │   Engine Core（纯 Python）    │
                    │  探测/抽帧/转写/AI/落盘/配置  │
                    └──────┬───────────────┬───────┘
                           │               │
              ┌────────────▼────┐   ┌──────▼──────────┐
              │ 桌面外壳 (Tk)    │   │ Web 外壳 (HTTP) │
              │ 双击即用 · 离线  │   │ 手机/平板访问   │
              └─────────────────┘   └─────────────────┘
```

- **桌面壳**：日常主力。全中文界面、拖拽文件夹、进度条、日志面板、设置页。
- **Web 壳**：同一台机器起一个本地服务，手机连同一个 Wi-Fi 打开地址就能**查看进度 / 审批命名 / 触发任务**。真正的算力仍在桌面机上。

### 4.3 关于"手机 App"

手机上真正需要的只是「看进度 + 点头确认」，不是「本地跑 Whisper」。因此：
- 短期：局域网 Web（1 天工作量，覆盖 90% 需求）
- 中期：给 Web 加 PWA（添加到主屏幕、离线缓存界面），外观与原生 App 无异
- 不做：原生 Android/iOS（除非有明确的离线移动端转写需求，届时另立项目）

### 5.2 不可违背的红线

| 编号 | 红线 | 原因 |
| --- | --- | --- |
| G1 | env 重定向必须发生在导入任何第三方库之前 | 否则 HF/CTranslate2 缓存会写进用户目录 |
| G2 | 所有产物落在 APP_ROOT 内 | 需求⑤；卸载就是删文件夹 |
| G3 | 引擎层禁止 import tkinter / fastapi | 保证双壳共用 |
| G4 | 工作线程不直接操作 UI，一律走队列 | 桌面壳是单线程 UI |
| G5 | 依赖装到 `libs/`，不写系统 site-packages | 便携化、零污染 |
| G6 | 可选依赖缺失必须优雅降级 | 缺 faster-whisper 时仍能做纯画面分析 |

## 6. 处理流水线（核心）

### 6.1 五阶段

```
[① 探测]  ffprobe：时长 / 音量 / creation_time / 是否已有软水印
    │
    ├────────────────► [②a 抽帧] ffmpeg 并发 N 路 ──────────┐
    │                  每个视频一个进程抽全部时间点           │
    └────────────────► [②b 转写] Whisper 单路串行(占 GPU) ───┤
                                                              ▼
                        [③ 合并] merge_map：视觉 + 字幕都到齐才放行
                                                              ▼
                        [④ AI 分析] 多模态模型 → title / plot / tags
                                                              ▼
                        [⑤ 落盘] ExifTool 写元数据 → 重命名 → 时间戳还原 → NFO / SRT
```

### 6.2 并发模型

| 阶段 | 并发策略 | 默认配额 | 理由 |
| --- | --- | --- | --- |
| ① 探测 | CPU 线程池 | `min(cpu, 8)` | 纯 IO + 短进程 |
| ②a 抽帧 | CPU 线程池（可选 NVDEC 混合通道） | `frame_workers=8`（GPU 通道 1） | 磁盘/CPU 密集，可并行 |
| ②b 转写 | **单路串行队列** | `whisper_workers=1` | GPU 独占，多路反而互相抢占显存 |
| ④ AI | 线程池 | `ai_workers=2~4` | 受本地推理服务吞吐限制 |
| ⑤ 落盘 | 串行 + 锁 | 1 | ExifTool 与重命名需避免同名竞争 |

> 关键：②a 与 ②b **互不阻塞**。无声视频跳过转写直接放行；有声视频等字幕到齐再进 ④。这是参考项目吞吐量的来源。

### 6.3 背压与保护

- **队列上限**：`ai_workers × 4`，防止抽帧远快于 AI 导致内存堆积（base64 帧很吃内存）。
- **熔断**：连续 5 次失败自动停止并提示原因（区分「上下文溢出」与「服务无响应」）。
- **停止语义**：置 StopToken → 不再调度新任务 → 在跑的视频跑完当前文件 → 已完成的改名保留 → 统计记 `cancelled`。

## 7. 功能开关与配置

### 7.1 开关总表（需求⑤：每个功能单独开关）

| 分组 | 开关 | 默认 | 关闭时的行为 |
| --- | --- | --- | --- |
| 输入 | `recursive` 递归子文件夹 | 开 | 只处理当前层 |
| 转写 | `enable_whisper` | 开 | 跳过语音，纯画面分析 |
| 转写 | `srt_vad_filter` VAD 过滤 | 开 | 静音段也送进模型 |
| 命名 | `include_date` 时间前缀 | 开 | 不加 `20261008_2313` |
| 命名 | `include_original` 原名后缀 | 关 | 不保留原文件名片段 |
| 命名 | `enable_marker` 处理标记 | 开 | 不加 `AI_RENAMED` |
| 命名 | `enable_skip` 跳过已处理 | 关 | 重跑全部（覆盖 NFO/SRT） |
| 输出 | `enable_nfo` 生成 NFO | 开 | 不产出 `.nfo` |
| 输出 | `write_metadata` ExifTool 写元数据 | 开 | 不写入视频内部属性 |
| 输出 | `move_failed` 失败移入 `_failed` | 开 | 失败文件留在原地 |
| 安全 | `dry_run` 预览模式 | 关 | 只演算不落盘 |
| 高级 | `frame_hwaccel` GPU 硬解 | 关 | 纯 CPU 抽帧（1080p 建议关） |
| 高级 | `auto_install_cuda` 自动补 CUDA 库 | 开 | 缺库时直接降级 CPU |
| 高级 | `verbose` 详细日志 | 关 | 只输出 INFO 及以上 |

```jsonc
{
  "ai": {
    "provider": "openai",              // openai | gemini
    "base_url": "http://127.0.0.1:8094/v1",
    "api_key": "1234",
    "model": "qwen3.8-27b",
    "timeout": 60, "retry_times": 2,
    "max_tokens": 5000, "temperature": 0.6, "top_p": 0.8,
    "enforce_json_mode": false
  },
  "frames": { "max_keyframes": 35, "max_side": 520, "workers": 8, "hwaccel": "none" },
  "whisper": { "enable": true, "model": "large-v3-turbo", "device": "auto",
               "compute_type": "int8_float16", "workers": 1 },
  "naming": { "template": "{date}_{title}", "date_format": "%Y%m%d_%H%M",
              "include_date": true, "include_original": false,
              "marker": "AI", "enable_marker": true, "enable_skip": false },
```

## 8. 目录规范（产物一律在应用目录内）

```
videoAIrenameAPP/
├─ app/                 # 源码（外壳 + 引擎 + 基础设施）
├─ bin/                 # ffmpeg.exe / ffprobe.exe / exiftool.exe
├─ libs/                # pip --target 安装的第三方包（运行期生成）
├─ models/              # Whisper / HF 模型缓存（≈1.6GB，运行期生成）
├─ cache/               # 设备探测结果等小缓存（如 whisper_device.json）
├─ tmp/                 # 临时帧与中间文件（任务结束清理）
├─ logs/                # 运行日志，按天滚动
├─ config.json          # 用户配置（运行期生成）
├─ 启动.vbs / 启动.bat  # 无控制台 / 保留控制台
└─ docs/                # 方案与说明
```

**启动第一段代码**就把 `TMP/TEMP/TMPDIR`、`HF_HOME`、`XDG_CACHE_HOME`、`XDG_DATA_HOME` 全部重定向到上述目录。这是"不到处乱放"的唯一可靠做法——很多库会在 import 时就读这些变量，所以重定向必须早于任何第三方导入。

## 9. 日志与可观测性（需求④）

| 层级 | 内容 | 去向 |
| --- | --- | --- |
| 启动 | 解释器、ffmpeg/exiftool 路径、CUDA 是否可用、模型名、Whisper 设备 | 日志面板 + `logs/run.log` |
| 任务 | 扫描到 N 个视频、跳过 M 个已处理、并发配置快照 | 同上 |
| 单文件 | 探测结果（时长/有无音轨）→ 抽帧数 → 转写字数 → **AI 开始/结束/耗时（含模型名与帧数）** → 改名前后 | 同上 |
| 异常 | 上下文溢出、JSON 解析失败、抽帧失败、AI 无响应 | WARN/ERROR 级别 + 界面红色标记 |

- 日志同时写文件与推界面；界面通过 `after()` 轮询队列消费（桌面壳）/ SSE 推送（Web 壳）。
- 单文件耗时统计在结束时汇总：平均秒/视频、成功/跳过/失败/取消计数。
- 长任务必须显示「当前正在处理哪个文件」，否则用户会以为卡死。

## 10. 依赖与离线策略

| 依赖 | 必需性 | 获取方式 | 缺失时 |
| --- | --- | --- | --- |
| Python 3.11+（带 tkinter） | 必需 | 便携包自带或系统已装 | 启动脚本报错并给出指引 |
| `openai>=1.0` | 必需 | 启动自动装到 `libs/` | 提示一键安装 |
| `faster-whisper` + `tqdm` | 按需 | 同上 | 自动降级为纯画面分析 |
| `google-genai` | 按需（Gemini 后端） | 同上 | 该后端不可用 |
| `tkinterdnd2` | 可选 | 同上 | 降级为按钮选择 |
| ffmpeg / ffprobe | 必需 | 自备放入 `bin/`；检测到缺失尝试 winget | 提示下载地址 |
| exiftool | 按需 | 同上 | 关闭「写元数据」仍可改名 |
| CUDA 运行库 | 按需 | 缺 `cublas64_12.dll` 等时只补装缺失的 pip 包到 `libs/` | 自动降级 CPU 转写 |

**离线能力边界**：模型与依赖就位后，全流程可在断网下运行（AI 走本地 llama.cpp / LM Studio，Whisper 走本地模型）。首次准备需要联网下载。

## 11. 实施路径（从现有代码迁移）

| 步骤 | 动作 | 产出 |

## 13. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 本地视觉模型上下文溢出（35 帧 × 高分辨率） | AI 阶段大面积失败 | 检测关键词后打印建议：降帧数 / 降分辨率；提供"自动降帧重试"开关 |
| 显存不足（Whisper + 视觉模型同时跑） | 崩溃或挂起 | Whisper 单路串行；启动时冒烟测试判定 GPU 可用性并缓存结果 |
| 中文路径 / GBK 终端乱码 | 子进程调用失败 | 所有子进程显式 UTF-8；exiftool 用 ArgFile 传参 |
| 命名不满意 | 用户不信任 | 预览模式 + 提示词模板可编辑 + 支持一键回滚（保留原名映射表 `data/rename_map.json`） |
| 双壳维护分叉 | 功能不一致 | 引擎单真源，外壳只做展示；新增能力先加引擎再加 UI |
